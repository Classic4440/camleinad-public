# Lyric videos

`build.mjs` makes one lyric video per released track and publishes it on the site's
**Videos** page (category "Lyric"). It uses your existing audio file and the track's lyrics;
nothing is generated by a video model.

- **Source:** `tracks.audio_url` + `tracks.lyrics` (+ `tracks.lyrics_synced` when it exists).
- **Timing:** `lyrics_synced` if present. Otherwise `align.py` finds when each line is sung
  (Whisper-based forced alignment; it only times the words, it does not change them).
- **Output:** MP4 in `video-files/lyric-videos/<track id>.mp4` plus a poster image, and a row
  in `videos` linked to the track (`videos.track_id`).
- **Skipped:** tracks without audio, tracks whose lyrics are placeholder text (< 80 characters),
  and tracks listed in `SKIP_TRACK_IDS` (already have an official lyric video).
- **Re-runs:** a video is rebuilt only when its track changed (`tracks.updated_at`).

## Run it

GitHub -> Actions -> **Lyric videos** -> Run workflow. Options: `only` (track ids), `force`,
`dry_run`. It also runs weekly. Needs the repo secret `SUPABASE_SERVICE_ROLE_KEY`.

## Fixing timing on one song

Edit that track's `lyrics_synced` in Supabase (`[{"line": "...", "time": 12.4}, ...]`), then run
the workflow with `only` = the track id and `force` on.

## Run locally

```
SUPABASE_URL=... SUPABASE_SERVICE_ROLE_KEY=... node scripts/lyric-videos/build.mjs
```
Needs `ffmpeg`/`ffprobe`, Node 20, and (for untimed tracks) Python 3 with `pip`.
